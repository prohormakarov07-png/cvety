# Демо-бот цветочного магазина «Флёр»

Витринный бот для показа клиентам: каталог с фото, корзина, доставка и самовывоз, сюрприз, открытка, заявки на букет, важные даты, админ-панель. Магазин и цены выдуманные. Всё, что нужно поменять под клиента, лежит в `config.py`.

## Что умеет

**Покупатель**
- Каталог: розы, букеты, цветы в коробке, растения, подарки. Фото, состав, размеры и цены, рейтинг по отзывам
- Подбор по поводу (день рождения, маме, свадьба...), по бюджету, хиты, поиск текстом («пионы»), избранное
- Корзина: количество, подарки к букету (конфеты, ваза, шары), промокод (`FIRST10`)
- Оформление: доставка (3 зоны, бесплатно от 5000 ₽ по городу) или самовывоз (−5%), получатель другой человек, режим «сюрприз», день и окно доставки, доставка к точному времени, открытка с текстом, комментарий, способ оплаты
- Мои заказы: статусы, отмена (не позднее чем за 3 часа), повтор заказа, оценка после доставки
- «Собрать букет на заказ»: повод, бюджет, гамма, упаковка, пожелания, заявка уходит флористу
- Важные даты: бот напоминает за 3 дня и предлагает подобрать букет
- Акции, доставка и оплата, отзывы, вопросы, адрес с картами, связь с администратором

**Администратор** (`/admin`)
- Новые заказы с кнопками статусов: принят, собираем, курьер выехал или готов к выдаче, выполнен, отмена. Клиент получает уведомление на каждом шаге
- Доставки на сегодня и завтра по времени
- Заявки на букет, ответ клиенту прямо из бота
- Статистика за 30 дней, стоп-лист (убрать товар из продажи), рассылка с предпросмотром
- «Демо-данные»: наполняет админку примерами для показа

## Запуск

```bash
python -m venv venv && source venv/bin/activate     # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                # впишите токен и ID администратора
python main.py
```

**ID администратора.** Напишите боту `/id`, впишите число в `ADMIN_IDS` (Telegram) или `MAX_ADMIN_IDS` (MAX) в `.env`, перезапустите бота. Затем `/admin` → «Демо-данные».

**Telegram в РФ** на российском сервере не открывается: нужен сервер за границей или прокси в `PROXY`. **MAX** работает без прокси. Бот в MAX регистрируется на business.max.ru (нужна верификация профиля).

## Как показывать клиенту
1. `/start` → «Каталог» → любой букет: фото, размеры, «В корзину»
2. Корзина → промокод `FIRST10` → «Оформить заказ»: доставка, получатель, сюрприз, открытка, окно, оплата
3. С телефона админа (`/admin`) принять заказ и провести по статусам: клиенту приходят уведомления
4. «Собрать букет на заказ», «Важные даты», «Стоп-лист»

## Адаптация под клиента
Меняйте `config.py`: название и адрес (`SHOP`), каталог (`PRODUCTS`), зоны и цены доставки (`ZONES`), окна (`DELIVERY_SLOTS`), промокоды, FAQ. Для фото положите свои картинки в `images/<ключ>.png` (800×800) вместо нарисованных: `python gen_images.py` пересоздаёт демо-картинки. Демо-отзывы в `SEED_REVIEWS` удалите перед боевым запуском. `SHOW_PHOTOS=0` в `.env` отключает картинки.

## Что проверено, а что нет
Логика (расчёты, окна доставки, оформление, статусы, отмена, отзывы, напоминания, админка) покрыта 20 тестами: `python -m unittest -v`. Все кнопки меню и админки обойдены автоматически без ошибок. Адаптеры Telegram и MAX прогнаны на заглушках библиотек: заказ от каталога до подтверждения, уведомления админу, рассылка. **С настоящими серверами Telegram и MAX этот бот не запускался.** Особенно проверьте отправку фото в MAX (если не получится, бот покажет карточку текстом). При ошибке пришлите текст из логов.

## Ограничения демо
Оплата онлайн не подключена (наличные, карта при получении, перевод по СБП по реквизитам). Курьеры и маршруты не учитываются. Состояние диалога хранится в памяти: после перезапуска незавершённое оформление начнётся заново, корзина и заказы сохраняются.
